# SHADOW — All-in-One Personal AI Product Blueprint

## Product promise
SHADOW is a personal AI agent, not only a chat interface. The Android app is the primary user experience; a shared backend provides model routing, memory, research and controlled tools. This project is separate from SWASTHYA SAATHI.

## Core product modules

1. **Assistant core**
   - Hindi and English conversations; preserve the user's language.
   - Task understanding, clarification when essential, planning and step-by-step execution.
   - Provider/model abstraction so free or local providers can be evaluated without tying the app to one vendor.
   - Honest capability and connectivity status; never show online/ready unless verified.

2. **Memory**
   - User-approved long-term preferences and project facts.
   - Conversation history with search, export, clear and per-item correction controls.
   - Sensitive information excluded by default; memory can be disabled.
   - User data isolated by account and protected in transit and at rest.

3. **Research**
   - Web search and page reading through server-side adapters.
   - Cite source links, distinguish facts from estimates, show retrieval time.
   - Respect robots, rate limits, site terms and provider quotas.

4. **Developer studio**
   - Code generation, explanation, debugging and project scaffolding.
   - Sandboxed build/test jobs with resource/time limits.
   - Show diffs and logs; never execute generated code on the user's device without explicit approval.
   - Export project files and provide build artifacts where supported.

5. **App and workflow builder**
   - Generate web/Android project templates and iterate on user requirements.
   - Build and test in isolated CI/workers; explain required secrets and permissions.
   - App installation is user-confirmed; no silent installation or sideloading.

6. **Task agent and integrations**
   - Tool registry with typed inputs, least privilege and audit log.
   - Read-only actions first; write actions require a preview and user confirmation.
   - Confirm before sending messages, deleting/editing files, purchases, publishing, changing settings or external account actions.
   - Allow cancellation and show progress/results.

7. **Android capabilities**
   - Voice input, text-to-speech, notifications/reminders and share-sheet integration.
   - File picker and document creation only after user selection/permission.
   - Device automation only through supported Android APIs, visible permissions and user-triggered actions.
   - Wake-word/background listening is a later opt-in feature after battery/privacy testing.

8. **Creative and productivity tools**
   - Documents, notes, summaries, presentations, image prompts and content planning.
   - Clearly separate generated drafts from actions that publish or send them.

## Architecture
- Android: Kotlin + Jetpack Compose, lifecycle-aware UI, secure token storage, permission-gated features.
- Backend: authenticated API, provider/model adapter, memory service, research adapters, task planner and tool execution gateway.
- Storage: per-user conversation and memory records; retention and deletion controls.
- CI: web build, Android unit/build checks, dependency/security checks, APK artifact upload.
- Secrets: server-side environment variables only; never embed provider keys or signing credentials in the APK.

## Delivery milestones and acceptance criteria

### M0 — Foundation and truthful status
- Keep main branch protected; work through reviewed feature branches/PRs.
- Verify current web and Android CI; document actual results.
- App shows accurate connection and permission states.

### M1 — Native Android shell
- Professional responsive dark interface and orb states.
- Chat composer, conversation list, settings, loading/error/empty states.
- Voice permission flow and speech recognition; no false claim of AI response until backend is connected.
- Debug APK generated by CI and manually installed/tested on a physical Android phone.

### M2 — Assistant API
- Authenticated chat endpoint, model adapter, streaming or clear progress feedback.
- Rate limits, request validation, safe error handling and health check.
- No provider secret in client code.

### M3 — Memory and history
- Opt-in memory, conversation persistence, search/export/delete and privacy controls.
- Automated isolation and deletion tests.

### M4 — Research
- Search/fetch adapters, source citations, timestamps, timeout and quota handling.
- Test unavailable, malformed and untrusted pages.

### M5 — Developer studio
- Code workspace, project templates, diff preview, sandboxed build/test and downloadable artifacts.
- Never run arbitrary code on the Android host.

### M6 — Safe task execution and integrations
- Tool permission manifest, dry-run preview, explicit confirmation, audit trail, cancellation and rollback where possible.
- Start with low-risk read-only tools.

### M7 — Android productivity and voice
- TTS, reminders, share sheet, file picker and supported app intents.
- Background/wake-word features remain opt-in and separately tested.

### M8 — Release readiness
- Accessibility, crash handling, offline behavior, performance, privacy/security review.
- User-owned release signing key; signed release APK/AAB and installation guide.

## Working rules
- Free-first: prefer local/open-source/free-tier options; disclose quotas, limits and any paid dependency before adoption.
- Do not promise unlimited capability or fully autonomous control. Explain Android, provider and account permission boundaries.
- Never claim a feature is complete until code, CI and relevant manual tests pass.
- Do not merge this project with SWASTHYA SAATHI.
